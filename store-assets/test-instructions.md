# Chrome Web Store 审核测试说明

## 登录信息

本扩展不需要账号、密码、订阅或付费功能。

## 建议测试环境

- Chrome 116 或更高版本
- 任意能够产生 Fetch / XHR 请求的普通 HTTP/HTTPS 页面
- 请勿在 Chrome Web Store、`chrome://` 页面或其他 Chrome 受保护页面测试
- 测试期间请关闭当前标签页的 Chrome DevTools，避免它接管调试连接

## 核心功能测试

1. 安装扩展并打开任意普通 HTTP/HTTPS 网页。
2. 点击工具栏中的 ApiViewer 图标，打开 Chrome 侧边栏。
3. 首次使用会出现显著的数据处理说明。此时扩展尚未连接 Debugger API，也不会读取网络请求。
4. 点击“同意并开始捕获”。Chrome 会显示当前标签页正在被调试的正常安全提示。
5. 刷新当前网页，或执行会产生 Fetch / XHR 的页面操作。
6. 验证请求列表显示方法、路径、状态码、耗时和大小。
7. 点击任意请求，切换“概览 / 请求头 / 请求 / 响应”标签，验证详情显示。
8. 点击复制按钮，验证 cURL 或正文仅在用户操作后写入剪贴板。
9. 点击“编辑并重发”，建议使用 GET 请求测试；修改查询参数后点击“发送请求”，验证响应结果出现在“响应”标签。
10. 点击捕获状态可以暂停和恢复；点击清空按钮可以清除当前列表。
11. 关闭侧边栏，验证 Chrome 的调试提示消失，表示扩展已解除调试连接。

## 权限和隐私验证

- `debugger`：仅在用户完成首次授权且侧边栏打开期间连接当前标签页。
- `storage`：仅保存设置与授权记录；捕获内容只保存在运行内存。
- `clipboardWrite`：仅由用户点击复制按钮触发。
- 扩展不向开发者服务器发送请求/响应数据。
- 扩展不加载或执行远程代码。
- 请求重放由用户明确点击触发，并发送到用户填写的目标 URL。

## 已知限制

- 侧边栏打开前的历史请求无法补抓。
- 二进制、流式、缓存或超过用户设置上限的响应可能无法预览。
- DevTools 和 ApiViewer 不能稳定地同时占用同一标签页的调试连接。
